# Hueometry: technology decisions (addendum to PLAN.md)

User decisions so far: accepts all defaults in PLAN.md section 10 except #4,
which becomes: ship through BOTH the Omarchy plugin marketplace AND a
standalone best-practice Omarchy install straight from the GitHub repo. The
user now asks to conclude every technology choice.

## Facts checked on this machine (2026-11-23)
- Omarchy 4.5.0-3; quickshell 0.3.2 (Omarchy build); Qt 6.12 base,
  declarative, multimedia, wayland, svg installed. qt6-shadertools not
  installed. node v26, qmake6, clang present. bend not installed.
- `omarchy-plugin-add` does `git clone <url>` of the whole repo, reads
  manifest.json at the clone root. `omarchy-plugin-validate` refuses ANY
  symlink anywhere in the folder (except .git). This repo has the symlink
  `.claude/skills -> ../.agents/skills`, required by the owner's working
  agreement. So this repo cannot itself be the marketplace plugin.
- Marketplace plugins are QML loaded into the long-running omarchy-shell
  (Quickshell) process. Kinds: bar-widget, panel, overlay (fullscreen),
  menu, service, bar. A plugin cannot deliver a compiled binary or run a
  package install without the baseline flagging it.
- Omarchy's own apps (omarchy-app skill): C++ + Qt Quick, qmake6 + make,
  one binary, Arch package via pkgbuild/PKGBUILD, bin/build, bin/test,
  bin/install (makepkg -fsi), .desktop + svg icon, setDesktopFileName,
  qsTr + src/i18n/<code>.json, theme accent from
  ~/.local/state/omarchy/current/theme/colors.toml, `?` shortcuts, Q quits,
  Ctrl+Z undo, atomic saves, "no generated files committed".
- Bend `-o x.mjs`: one ES module = Bend JS runtime + program +
  `export default { fn: run_lib(...) }`. The runtime's Node-specific parts
  (process, require, BigInt, Atomics) sit in the IO path; whether the pure
  module runs in Qt's V4 JS engine is unverified.

## Consequence
Only one stack can serve both channels from one codebase: Qt Quick/QML,
because the marketplace channel must run inside the Quickshell process.
So: one shared QML game module + Bend's engine.mjs, two thin hosts.

## Decisions (recommended)

1. UI framework: Qt 6 Quick (QML + JS), Qt 6.12 as shipped by Omarchy 4.5.
   Rejected: Godot, Tauri/Electron/web, SDL/raylib, Rust/Bevy: none can run
   as a marketplace plugin, and none hosts Bend's JS module without glue.
2. Engine boundary: Bend -> engine.mjs, imported by QML
   (`import "engine.mjs" as Engine`), wrapped by one QML/JS adapter. Used
   identically by both hosts. Generator and hint search run in a
   WorkerScript so the shell's UI thread never stalls. Gate in M1: the
   module must run in Qt's JS engine (QJSEngine test). Fallback if it does
   not: a small compatibility shim; if impossible, stop and report
   (standalone could use a native Bend sidecar; the marketplace channel
   could not ship the game).
3. Two hosts, one shared QML module (`qml/Hueometry/`, no Quickshell or
   Quattro imports inside it; host services injected through one `Host`
   object: storage, close/quit, fullscreen, language, scale):
   a. Standalone app: thin C++ host (QGuiApplication, setDesktopFileName,
      QSaveFile storage, translator), qmake6 + make, Omarchy app layout,
      opens fullscreen by default (Hyprland would otherwise tile it), F11
      toggles. C++ owns platform services only; Bend owns the rules.
   b. Marketplace plugin: `overlay` kind (fullscreen game) plus a
      `bar-widget` kind (orb button that summons it), storage through
      Quickshell FileView. Plugin id `io.github.bvisagie.hueometry`.
4. Repositories:
   - `BVisagie/omarchy-hueometry`: all sources, proofs, tests, PKGBUILD,
     agent files. Standalone install from here.
   - `BVisagie/omarchy-hueometry-plugin`: generated by the release
     workflow: manifest.json, README (install/remove), LICENSE, preview.png,
     the shared QML, assets, engine.mjs. No symlinks, no sources, no tests.
     Normal commits per release (no force-push: `omarchy plugin update`
     pulls). This is the repo submitted to the marketplace.
5. Generated engine: commit `engine/dist/engine.mjs` in the main repo, with
   a CI check that a fresh build from the pinned Bend matches it byte for
   byte. Deliberate exception to the "no generated files" convention: brief
   7.9 says users never install Bend, and `bin/install` from a clone must
   work without it.
6. Standalone install paths (best practice first):
   - `git clone … && cd omarchy-hueometry && bin/install` (makepkg -fsi).
   - Prebuilt `hueometry-<ver>-x86_64.pkg.tar.zst` on each GitHub Release,
     `sudo pacman -U <file>`.
   - AUR package after 1.0 (optional), so `omarchy-pkg-aur-add hueometry`.
   Package name, binary, .desktop, icon and Wayland app id: `hueometry`.
   Removal: `sudo pacman -R hueometry`; saves stay unless the README's
   purge step is run.
7. Shared saves: both channels use `$XDG_DATA_HOME/hueometry/` for progress
   and `$XDG_CONFIG_HOME/hueometry/` for settings, versioned JSON, atomic
   writes, so a family can switch channel and keep progress. Autosave the
   current puzzle (id + moves) so closing the overlay never loses a game.
8. Rendering: Qt Quick scene graph; illustrated raster layers (WebP, sized
   for 4K, mipmapped), SVG for icons and UI; Qt's built-in MultiEffect for
   glow, shadow, blur; QtQuick.Particles for celebrations; Qt Quick
   animations, all routed through one motion setting for reduced motion.
   No custom shaders in v1 (they need qsb build tooling and committed
   binaries in the plugin repo).
9. Audio: Qt Multimedia. SoundEffect (WAV) for clicks and chimes;
   MediaPlayer + AudioOutput for ambience and music (Ogg Opus). Separate
   music and effects volumes, mute. M1 checks it loads inside Quickshell.
10. Fonts: one bundled OFL-licensed rounded sans for game text, loaded with
   FontLoader; picked in M7.
11. Omarchy conventions: follow them for keys (`?` help, Q quit with
   confirm, Ctrl+Z undo, Space main action), qsTr on every string with the
   Omarchy language file (English only in v1), .desktop, icon, scaling.
   Deviation: the game does NOT take the Omarchy theme accent; jungle art
   has its own palette (theme packs own colour).
12. Testing:
   - Bend: `bend PROOF.bend --verdict`.
   - Engine: Node's built-in `node:test` + `fast-check` (pinned dev
     dependency) against engine.mjs; golden replays; plus the same suite
     run inside QJSEngine to keep the Qt-engine gate permanent.
   - QML: Qt Quick Test (qmltestrunner) offscreen for adapter, layouts,
     keyboard focus, screens.
   - C++ host: Qt Test (Omarchy convention).
   - Plugin: `omarchy plugin validate` + qmllint against
     $OMARCHY_PATH/shell, in CI and before each release.
13. CI: GitHub Actions in an `archlinux` container: pinned Bend (exact
   version + checksum), elan + Lean 4.34.0 (cached kernel), Qt 6 packages,
   node. Jobs: proofs, engine tests, drift check, QML tests, makepkg build,
   plugin-repo build + validate.
14. Releases: SemVer tags, CHANGELOG.md; release workflow builds the
   package, attaches it to the GitHub Release, and commits the plugin repo.
   Marketplace updates go through its verification form (manual, by rule).
15. Art and audio sources: exported assets in git; layered sources
   (.kra/.svg/.blend/DAW projects) in Git LFS under `art-src/` so normal
   clones stay small. Who makes the art stays open (PLAN.md #6).

## Roadmap changes
- M1 adds the Qt gate: engine.mjs runs in QJSEngine and in a Quickshell
  QML import; QtMultimedia loads inside Quickshell.
- Old M4 "technology selection" becomes "Host skeletons": shared QML module
  with a greybox board running in both hosts; plugin repo generated and
  passing `omarchy plugin validate`; package installs via bin/install.
- M9 shrinks to polish of both channels and marketplace submission.
